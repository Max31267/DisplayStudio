# MDP1, версия 1 — реализованная часть

USB Serial/JTAG ESP32-C3 представлен в Windows COM-портом. В приложении установлен baud rate 921600; встроенный USB-контроллер не превращает это число в гарантированную скорость передачи.

## Пакет

Все целочисленные поля little-endian. Единственное исключение — каждый пиксель RGB565 передаётся старшим байтом вперёд, как ожидает выбранная конфигурация ST7789.

| Смещение | Размер | Содержимое |
|---|---:|---|
| 0 | 4 | ASCII `MDP1` |
| 4 | 1 | Версия: `1` |
| 5 | 1 | Тип сообщения |
| 6 | 2 | Длина payload, 0…7688 |
| 8 | 4 | Номер пакета |
| 12 | 4 | CRC32 IEEE |
| 16 | N | Payload |

CRC считается по байтам 4…11, затем payload. Полином reflected `0xEDB88320`, начальное значение `0xFFFFFFFF`, результат инвертируется. Канонический вектор `123456789` → `0xCBF43926`.

Принимающий парсер использует фиксированный буфер 7704 байта, допускает дробление/объединение чтений и ищет magic после повреждения. Ошибка CRC или неподдерживаемый заголовок вызывает запрос полного кадра. Если заголовок указывает допустимую, но неверную длину, парсер может ждать недостающих байтов; таймаут ПК приводит к повторному подключению. Подтверждение потерянного пакета не угадывается.

## Сообщения

| Код | Тип | Payload |
|---|---|---|
| 1 | Hello | Пусто для прежнего ответа; `[1]` запрашивает расширенный. Начинает новую сессию с любым номером пакета |
| 2 | Capabilities | `width:u16, height:u16, maxPayload:u16, freeHeap:u32`; после Hello `[1]` дополнительно `features:u32` |
| 3 | FrameBegin | `frameId:u32, full:u8` (`0` или `1`) |
| 4 | Pixels | `x:u16, y:u16, width:u16, height:u16`, затем RGB565 |
| 5 | FrameEnd | `frameId:u32` |
| 6 | Ack | Пусто; номер равен номеру подтверждаемого пакета |
| 7 | RequestFull | Пусто; сессия требует повторного согласования и полного кадра |
| 8 | TimeSync | `localWallSeconds:u64` |
| 9 | Ping | Пусто |
| 10 | SetBrightness | `percent:u8`, от 0 до 100; только между кадрами и при features bit 0 |

Начиная с 0.4.1 хост сначала отправляет Hello `[1]`. Новая прошивка возвращает 14 байт Capabilities; бит 0 `features` означает аппаратное управление подсветкой. Остальные биты зарезервированы. При RequestFull от старой прошивки хост повторяет пустой Hello и принимает прежние 10 байт; команды яркости ей не отправляются. Старая программа получает от новой прошивки прежний ответ на пустой Hello. При `BL=-1` бит подсветки отсутствует.

SetBrightness подтверждается Ack только после успешного применения PWM. Неверная длина, значение >100, нарушенный номер, команда внутри кадра или отсутствие управления подсветкой вызывают RequestFull без изменения яркости. Команда не меняет пиксели и базу сравнения кадров. Значение 0 выключает подсветку, 100 задаёт максимум. На переподключении приложение повторно отправляет сохранённое значение перед первым кадром; очередь старых положений ползунка не накапливается. Прошивка сохраняет последнее значение в NVS через 2 секунды без изменений и использует его при включении, включая резервные часы. До первого сохранения — 80%. Ошибка записи NVS не прерывает USB/PWM; значение остаётся в RAM, сохранение повторяется через 5 секунд. Если NVS не удалось открыть при запуске, уровень хранится только в RAM до перезагрузки.

`localWallSeconds` — количество секунд от 1970-01-01 **по локальным часам ПК**, без дополнительного часового смещения. Это не UTC Unix timestamp. Прошивка использует остаток от деления на сутки для резервных HH:mm. После обесточивания нужно новое TimeSync. Хост синхронизирует время при подключении и раз в минуту.

## Правила обмена

1. ПК посылает Hello, получает Capabilities с тем же номером. Следующий пакет имеет номер `Hello.sequence + 1` с переполнением u32.
2. Остальные команды получают Ack; RequestFull означает отказ. Одновременно ожидается ответ только на один пакет. Таймаут — 2 секунды.
3. Кадр состоит из FrameBegin, одного или нескольких Pixels и FrameEnd. На новом подключении и после ошибки первый кадр обязан быть полным. Полный кадр проверяется по покрытию всех 225 блоков.
4. В этой реализации `x`, `y`, `width` кратны 16; `height` равна 16. Прямоугольники не выходят за пределы 240×240. Максимальная полоса — 240×16, то есть 7680 байт пикселей + 8 байт координат.
5. Получатель проверяет CRC, последовательность, длину и границы **до вывода конкретного блока**. Ack на Pixels отправляется после окончания SPI DMA.
6. ПК обновляет базовый кадр сравнения только после Ack на FrameEnd. При неизвестном результате он повторно согласует сессию и передаёт полный кадр.
7. Даже при неподвижном изображении ПК посылает Ping раз в секунду. После 5 секунд без допустимых команд прошивка переходит к резервным часам и требует новой сессии.

Внутри одного кадра области выводятся последовательно. Полного буфера и атомарного переключения кадров в ESP32 нет: до восстановления могут быть видны уже принятые части незавершённого кадра. CRC обеспечивает целостность блока, а не скрытие всего кадра до FrameEnd. Плавность и разрывы изображения требуют испытаний на панели.

Capabilities и Ack имеют собственные CRC. Дублирование подтверждённого пакета без нового Hello считается нарушением последовательности. Палитры, RLE, загрузка ресурсов и локальные GIF пока не согласуются и не поддерживаются.
